# GL 总账使用说明

从 Axibiz 0.10.0 起，新业务单据可自动生成复式分录，并提供手工 Journal Entry、总账明细和试算平衡。

## 首次启用

1. 先备份公司数据，在 Setup → GL Setup 核对 GL 本币及应收、应付、银行、收入、汇兑、税款调整科目的关联。
2. 本币初始取升级时的公司默认币种，与之后新单据的结算币种分别管理。本币在首次过账后固定；改变默认结算币种不会改变 GL 本币。首次过账前改变本币时，请重新检查已存草稿的汇率。
3. 历史单据不自动生成分录。按采用的启用日期和范围，以手工分录登记期初资产、负债、权益等余额。不要把同一笔旧业务既计入期初，又重复录入收入或费用。
4. 新收款即使关联旧发票也会入账，因此历史应收余额应先通过期初分录处理。历史费用编辑不会自动补入 GL，必要的历史更正需手工调整。

GL Setup 的默认关联如下，可替换为相同类型的启用科目。已有公司实际编号可能不同，请以界面关联为准。

| 用途 | 默认科目 | 类型 |
| --- | --- | --- |
| 应收 | 1100 Accounts Receivable | Asset |
| 应付 | 2000 Accounts Payable | Liability |
| 银行 | 1010 Bank - CAD | Asset |
| 收入 | 4000 Service Revenue | Income |
| 汇兑损益及税务折算尾差 | 6300 Foreign Exchange Gain or Loss | Expense |
| 税款调整 | 6400 Sales Tax Adjustments | Expense |

默认银行科目用于收款和税款现金记录，各付款方式暂不分别映射银行账户；需要使用其他银行账户时在 GL Setup 调整。科目名称中的 CAD / USD 是标签，不限制单据币种。新增的 6300、6400 加上原服务业模板，标准新公司共有 32 个科目。

## 手工 Journal Entry

左侧 Accounting → Journal Entries → New Journal。

- 顶部选择币种、日期和汇率，汇率方向为 `1 分录币种 = 汇率 × GL 本币`；本币汇率为 1。可使用本地报价，也可手工填写最多八位小数的汇率。
- 初始提供八行，科目支持名称或编号前缀查找。每个有效行只能有借方或贷方金额，金额以两位小数录入；可以添加、复制和删除行。
- Name 可关联一个 Customer 或 Vendor，也可留空。输入候选文字后必须选择真实记录，或清空输入；不会把未选定的文字当成记录保存。
- Description 是行说明，Memo 是整张分录备注。Tax reference 仅为备注，不自动计税或影响销售税子账。
- 附件每个最多 20 MB，与草稿一起事务保存，存入 SQLite，备份会一并保存。附件可另存为文件，程序不自动打开或执行附件。已过账附件不可改写。
- Save 保存草稿并留在界面；Save & Close 保存草稿并关闭。草稿不进入报表，首次保存分配 JE 编号，重复保存更新同一草稿。
- Post 要求至少两行、有效启用科目、借贷相等且大于零，原币和本币均平衡。失败保留输入并回滚编号和附件。
- 已过账分录只读。手工分录可在 Reverse 中填写日期及原因生成反向分录，原分录保留，不能重复冲销。冲销日期不得早于原分录，也必须属于开放期间。
- Cancel 或 Esc 有未保存修改时会询问是否放弃。关闭操作不等于冲销。

Setup → Numbering 可配置 journal 的前缀、位数和下一编号，默认 `JE0001`。编号保存后固定。外币按整数分和定点汇率换算，分值尾差会分配以保证本币借贷平衡；已过账汇率不会随在线更新改变。

## 自动入账

| 来源操作 | 借方 | 贷方 |
| --- | --- | --- |
| 新 Invoice | 应收账款（含税） | 服务收入（未税）、对应销项税科目 |
| 新收款 | 默认银行 | 应收账款；必要时记汇兑差额 |
| 新 Expense | 各行费用成本、允许抵扣的进项税科目 | 应付账款（含税） |
| 税款缴纳 | 对应应缴税科目 | 默认银行 |
| 税款退款 | 默认银行 | 对应应缴税科目 |
| 税款调增 | 税款调整 | 对应应缴税科目 |
| 税款调减 | 对应应缴税科目 | 税款调整 |

GL 与来源单据在同一个数据库事务中保存；汇率、科目或期间校验失败时，整次操作回滚，不会留下只有单据或只有分录的状态。

Task 新建、Completed 及明细中的预算成本不直接生成 GL；收入在新 Invoice 创建时入账，实际费用以 Expense 为来源。Task 的管理利润与 GL 的全部期间损益可能采用不同范围。手工往来分录不会改变 Invoice 的已收/未付余额，也不会修改来源 Task 的状态。

修改已入账费用时，原分录保留并生成冲销，再保存当前费用的新分录。重复保存未变化的费用不重复过账。关联 Task 已取消或已开票的费用仍遵守原有锁定规则。历史费用不会因为编辑而被自动追溯入账。

撤销收款或税款会生成反向分录；来源记录仍保留原撤销状态和审计记录。自动分录不能从 Journal Entry 页面直接冲销，请在来源页面处理。Invoice 和 Expense 详情可打开关联 GL 分录，历史未入账单据有明确提示。

外币收款按原发票应收本币余额分摊，最后一笔结清剩余金额；银行按收款汇率折算，差额进入汇兑损益。GL 本币为 CAD 时，费用可抵扣税使用税务子账已保存的 CAD 快照，折算差额单独进入汇兑科目，避免改写旧税额。

自动入账优先读取本地、单据日期及之前七天的报价；无日期的手工汇率可作为明确覆盖。缺少适用报价会停止保存并提示补充报价，不能用未来自动报价替代旧日期的汇率。在线更新仍遵循启动同步及缺失时查询，不增加每小时检查。

Expense 目前作为应付费用单处理，尚无供应商付款子账。实际支付可手工借记应付、贷记银行，并关联 Vendor。此类分录不会把 Expense 页面变成带付款状态的应付管理系统。

## 总账与试算平衡

左侧 General Ledger 或 Report → General Ledger / Trial Balance。

- General Ledger 按日期区间和科目筛选，列出 Journal#、来源、科目、说明、原币借贷及本币借贷。
- 本币余额列按各科目逐行累计，借方为正、贷方为负。选择单个科目时显示期初和期末余额。
- Trial Balance 按截止日期计算各科目的本币借方或贷方余额，显示借方、贷方及差额合计。
- 只有已过账分录参与计算；原分录与其冲销均计入所属日期，草稿不计入。
- 点击明细 ID 可查看分录；两类报表支持 CSV 导出，拒绝覆盖已有文件，并转义可能被表格软件当成公式的文本。

本版提供总账与试算平衡，未实现完整损益表、资产负债表、自动年度结转、供应商付款子账或往来核销。期初与手工调整须根据实际业务范围核对。

## 期间与数据保护

GL Setup 的“锁定至”接受 `YYYY-MM-DD`，包含截止当天，留空表示不锁定。锁定期间拒绝新过账和已入账费用的原日期冲销重记。可在之后的开放日期做冲销或手工调整；解锁必须主动修改设置并保存，设置变更纳入审计。此功能为 GL 过账控制，不替代销售税申报期封账。

已过账分录、明细和附件有数据库触发器保护。已引用科目不能改变类型；GL 关联科目需先更换关联，才能停用。备份验证检查分录平衡、本币金额、来源快照和冲销关系。升级前自动备份，原公司 ID、历史发票和费用数据保留。
